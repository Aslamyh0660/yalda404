environment is authorised for the existing repository only; creating a
repository returns `403 Resource not accessible by integration`. Consequently
there is no `sharea-verify` repository, no Pages deployment, and no permanent
public URL yet — and the live site row in README says so.

**The bot portrait is still a placeholder.** `public/brand/profile.png` is a
generated stand-in (flat navy disc with the Material robot glyph), the brief's

no viewport screenshots, no keyboard walk. Everything machine-checkable on the
rendered HTML and the shipped CSS *is* checked; the list of browser-only checks
is in README → "Quality checks", with the exact commands.

## Finishing it — three steps

1. **Create the repository** (either you create `sharea-verify` and give the
   agent push access, or run it yourself):

   ```bash
   gh repo create Aslamyh0660/sharesa-verify --public \
     --source=. --remote=sharea --push
   ```

2. **Turn on Pages once** — *Settings → Pages → Source: GitHub Actions*. The
   workflow in `.github/workflows/deploy-pages.yml` then builds and publishes on
   every push to `main`, and the page appears at

   ```
   https://aslamyh0660.github.io/sharesa-verify/
   ```

   If the page is hosted anywhere else, change `SITE_URL` in
   `src/lib/site.config.ts`, the canonical/`og:url`/`og:image` lines in
   `index.html`, `public/robots.txt` and `public/sitemap.xml` first.

3. **Re-verify the QR code against the live URL** — this is the step that
   matters before anything is printed:

   ```bash
   npm run qr && npm run verify:qr
   ```

   The committed code currently encodes
   `https://aslamyh0660.github.io/sharesa-verify/`, which is the intended target
   and is **not live yet** — do not print it before step 2 succeeds.

## Alternative hosts (no GitHub repository needed)

`sharea-verify-dist.zip` is a complete static build. Drag it onto
<https://app.netlify.com/drop>, or use *Cloudflare Pages → Upload assets*, and
the page is live in about a minute at a `*.netlify.app` / `*.pages.dev` address;
then do step 3 with that address. The like counter needs the Worker deployed
separately (`npm run likes:migrate -- --remote && npm run likes:deploy`) and its
URL passed as `VITE_LIKES_API_BASE`.
